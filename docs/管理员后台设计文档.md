# 管理员后台设计文档（已实施）

> 状态：**已评审通过并实施**。本文档记录最终落地的方案与决策。

## 0. 评审结论（用户已确认）

| 开放问题 | 决策 |
|------|------|
| 角色范围 | 一期只做 **ADMIN**，MODERATOR 留作二期扩展 |
| 恢复功能 | **要**。删除为逻辑删除，管理端可一键恢复已删除帖子 |
| 初始管理员 | 启动时自动创建管理员（用户名 `jiangma.admin.username` 默认 admin；密码 `jiangma.admin.password`，未配置则随机生成并打印日志），不覆盖已有账号密码 |
| 二期范围 | **分类/标签管理提前到一期实施**（标签按项目设计）；数据看板、审计日志仍留二期 |

## 1. 为什么要做

| 现状 | 问题 |
|------|------|
| 帖子/评论只有作者本人能删除 | 恶意评论、广告帖、违规内容无人可处理 |
| `user.role` 字段（USER/ADMIN）已存在，数据库已有 `system`（ADMIN）账号 | 角色体系是空摆设，没有任何权限分层 |
| 前端 `stores/user.js` 已有 `isAdmin` / `isModerator` getter | 说明最初就规划了管理端，只是没落地 |
| 分类/标签只能靠迁移脚本维护 | 运营调整（改名、合并、新增项目分类）必须改代码 |

结论：加一个轻量管理员后台，补齐内容审核 + 用户管理 + 基础运营能力。

## 2. 角色与权限

**一期只做 ADMIN**，权限结构预留 MODERATOR（版主）扩展。

| 能力 | ADMIN | MODERATOR（二期） | 普通用户 |
|------|:---:|:---:|:---:|
| 删除/恢复任意帖子 | ✅ | ✅ | 仅自己的 |
| 删除任意评论 | ✅ | ✅ | 仅自己的 |
| 禁用/启用用户 | ✅ | ❌ | ❌ |
| 分类/标签管理 | ✅ | ❌ | ❌ |
| 数据看板 | ✅ | ✅ | ❌ |
| 访问 `/admin` 页面 | ✅ | ✅ | ❌ |

判定依据：`user.role` 字段，JWT 中已携带 `role` claim，后端以 Spring Security `hasRole('ADMIN')` 为准（前端菜单显隐只是体验，不是安全边界）。

## 3. 功能清单（一期已实现）

### 3.1 内容管理
- **帖子管理**（`/admin/posts`）：分页列表，筛选（关键词/项目/是否含已删除），操作：删除（逻辑删除）、恢复、跳转详情
- **评论管理**（`/admin/comments`）：分页列表，按帖子 ID 筛选，内容摘要悬浮显示全文，操作：删除

### 3.2 用户管理
- 用户列表（`/admin/users`）：用户名/昵称/邮箱/角色/注册时间/状态，关键词与状态筛选
- 操作：禁用（status=0）、启用（status=1）
- 保护规则：不能禁用自己、不能禁用 ADMIN 账号（后端强校验）

### 3.3 项目与标签管理（按项目设计）
- **项目管理**（`/admin/categories`）：新增/编辑（名称、描述、排序）/删除；仅当项目下无知识点时允许删除（后端强校验），列表展示每个项目的知识点数
- **标签管理**（`/admin/tags`）：标签归属设计——
  - `tag.category_id` 为空 = **全局标签**，所有项目发布时均可选用
  - `tag.category_id` 非空 = **项目专属标签**，仅在对应项目中可选
  - 发布页（`EditorView`）标签选项随所选项目动态过滤：全局标签 + 该项目专属标签；切换项目时自动清除失效的已选标签
  - 公开接口 `GET /api/tags?categoryId=` 返回「该项目标签 + 全局标签」
  - 删除标签会先解除与帖子的关联（`post_tag` 清理），再删除标签本身
- **操作日志（审计）**（`/admin/logs`）：基于 AOP 自动记录所有写操作——
  - 实现：`@OpLog` 注解 + `OperationLogAspect` 切面（`spring-boot-starter-aop`），方法成功返回后写入 `operation_log` 表；日志写入失败只记警告，不影响业务
  - 记录内容：操作人（ID+用户名）、模块（AUTH/USER/POST/COMMENT/LIKE/FOLLOW/ADMIN）、动作、目标类型与 ID、详情（自动追加参数，敏感参数如密码用 `recordArgs=false` 排除）、来源 IP、时间
  - 覆盖范围：登录/注册/退出、发帖/编辑/删除/学习状态、评论/删评、点赞、关注、以及全部管理端操作
- 数据看板：**二期再做**

## 4. 技术方案（已落地）

### 4.1 后端
- **路由隔离**：所有管理接口统一前缀 `/api/admin/**`，SecurityConfig 中：
  `.requestMatchers("/api/admin/**").hasRole("ADMIN")`
- **控制器**：`AdminContentController`（帖子/评论）、`AdminUserController`（用户）、`AdminTaxonomyController`（项目/标签），服务层 `AdminContentService` / `AdminUserService` / `AdminTaxonomyService`
- 删除沿用逻辑删除（`deleted=1`），帖子支持恢复（`restoreById` 置回 `deleted=0`）
- 被禁用用户登录时已有拦截，JWT 过滤器也会拒绝已禁用用户，无需额外开发
- **管理员初始化**：`AdminInitializer`（ApplicationRunner）启动时若 `admin` 账号不存在则创建（BCrypt 加密），存在但非 ADMIN 则提升角色；不覆盖已有密码
- **数据库迁移**：`V12__admin_taxonomy.sql` —— `tag` 表新增 `category_id` 列与索引，并把存量标签回填到编号最小的项目

### 4.2 前端
- **路由组** `/admin`（独立布局 `AdminLayout`：左侧菜单 + 内容区），子路由：
  - `/admin/posts` 内容管理（默认页）
  - `/admin/comments` 评论管理
  - `/admin/users` 用户管理
  - `/admin/categories` 项目管理
  - `/admin/tags` 标签管理
- **路由守卫**：`requiresAuth + requiresAdmin`；进入管理页前若未拉取过用户资料会先 `fetchProfile()`，非 ADMIN 重定向回首页
- **入口**：`AppHeader` 用户下拉菜单中，`userStore.isAdmin` 为 true 时显示「管理后台」
- 页面统一 Element Plus `el-table + el-pagination + ElMessageBox.confirm` 风格

## 5. API 设计（一期已实现）

统一响应 `{ code, message, data }`，分页参数沿用 `page/size`（后端已有 100 上限保护）。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/admin/posts?page&size&keyword&authorId&categoryId&includeDeleted` | 帖子管理列表（含草稿/已删除） |
| DELETE | `/api/admin/posts/{id}` | 删除帖子（逻辑） |
| PUT | `/api/admin/posts/{id}/restore` | 恢复帖子 |
| GET | `/api/admin/comments?page&size&postId&authorId&includeDeleted` | 评论管理列表 |
| DELETE | `/api/admin/comments/{id}` | 删除评论（逻辑） |
| GET | `/api/admin/users?page&size&keyword&status` | 用户列表 |
| PUT | `/api/admin/users/{id}/status?status=0\|1` | 禁用/启用用户 |
| GET | `/api/admin/categories` | 项目列表（含知识点数） |
| POST | `/api/admin/categories` | 新建项目 `{ name, description, sortOrder }` |
| PUT | `/api/admin/categories/{id}` | 编辑项目 |
| DELETE | `/api/admin/categories/{id}` | 删除项目（有知识点时拒绝） |
| GET | `/api/admin/tags?categoryId` | 标签列表（含引用数） |
| POST | `/api/admin/tags` | 新建标签 `{ name, categoryId|null }` |
| PUT | `/api/admin/tags/{id}` | 编辑标签 |
| DELETE | `/api/admin/tags/{id}` | 删除标签（先解除帖子关联） |
| GET | `/api/admin/logs?page&size&module&keyword` | 操作日志（模块筛选+关键词搜索） |

二期补充：`GET /api/admin/stats` 数据看板、审计日志。

## 6. 安全要点

- 授权以后端 `hasRole('ADMIN')` 为唯一依据，前端隐藏入口仅为体验
- 管理员操作对象校验：不能禁用自己、不能禁用 ADMIN 账号
- 删除项目前强校验知识点数为 0；删除标签先清理 `post_tag` 关联
- 初始密码建议通过环境变量注入，**生产环境必须**通过 `jiangma.admin.username/password`（或环境变量 `JIANGMA_ADMIN_USERNAME` / `JIANGMA_ADMIN_PASSWORD`）改为强密码，并在首次登录后修改
